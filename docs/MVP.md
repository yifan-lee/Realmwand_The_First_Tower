# Realmwand: The First Tower — MVP 设计文档

> 状态：初稿  
> MVP 目标：做出一段 10～20 分钟、可以从头玩到尾的第一层流程，用来验证探索、成长、ATB 战斗和机关解谜能否组成有趣的核心循环。

## 1. 游戏概念

### 一句话介绍

这是一款 2D 俯视角角色扮演游戏。玩家在高塔中以格子方式探索，通过 ATB 战斗击败怪物、收集装备和道具、触发机关，并寻找通往下一层的方法；最终目标是在塔顶找回失去的魔杖。

### 玩家体验目标

- 探索未知房间时有好奇和轻微紧张感。
- 捡到装备、升级或击败强敌后，能明显感到角色变强。
- 观察环境并解开机关后，获得“我找到了办法”的满足感。
- 第一层结束时，愿意继续探索第二层。

### 核心循环

1. 在地图上逐格探索。
2. 发现怪物、宝箱、道具、NPC 或机关。
3. 进入战斗或进行互动。
4. 获得经验、金币、装备、道具或线索。
5. 提升角色能力，解开本层机关。
6. 开启楼梯，进入下一层。

## 2. MVP 可玩片段

### 开始状态

- 玩家出现在高塔第一层入口。
- 玩家没有魔杖，持有一件最基础的武器或徒手攻击能力。
- 用一句简短提示交代目标：寻找通往第二层的路。

### 建议流程

1. 玩家学习上下左右逐格移动。
2. 玩家在岔路附近发现第一件可拾取道具。
3. 玩家遇到第一只较弱的教学怪物，进入 ATB 战斗。
4. 胜利后获得经验和金币。
5. 玩家找到一件装备，并在菜单中装备它。
6. 玩家面对第二只更强的怪物，感受到装备带来的提升。
7. 玩家从环境或提示中理解机关规则。
8. 玩家触发机关，解除楼梯的封锁。
9. 玩家走到楼梯处，出现“第一层完成”画面，MVP 结束。

### 地图规模

- 1 张第一层地图。
- 5～8 个小房间或明确区域。
- 1 条主路线，最多 1～2 条短支路。
- 1 个机关谜题。
- 1 个通往第二层的楼梯出口。

地图应足够小，让测试者无需攻略也能在 20 分钟内完成。

## 3. MVP 功能范围

### 必须完成

#### 地图探索

- 2D 俯视视角。
- 玩家只能上下左右移动。
- 每次移动一格，移动过程有短暂的平滑动画。
- 墙壁、障碍物和关闭的门会阻挡移动。
- 玩家可以面对并互动当前方向上的物体。

#### 场景互动

- 可以拾取地图上的道具。
- 可以打开宝箱或调查物体。
- 可以触发开关。
- 可以使用已开启的楼梯。
- 简单文本框能够显示提示和少量对白。

#### ATB 战斗

- 探索时接触地图上的怪物后进入独立战斗场景。
- 玩家和敌人各自拥有 ATB 进度。
- 进度满后，角色可以执行行动。
- MVP 中玩家行动只有：普通攻击、使用道具、逃跑（逃跑也可推迟到后期实现）。
- 敌人只有普通攻击。
- 包含生命值、攻击力、防御力和速度四项基础属性。
- 战斗胜利后获得经验和金币。
- 玩家生命值归零时显示失败画面，并允许重新开始第一层。

#### 成长

- 经验达到要求后提升等级。
- 升级至少提高生命值和攻击力。
- 金币能够被获得和保存，但 MVP 中可以暂时没有商店。

#### 背包与装备

- 可以查看持有的道具。
- 可以在战斗中使用一种恢复道具。
- 至少有一个装备栏，例如“武器”。
- 装备会改变角色属性。
- 地图上的物品被拾取后不会重复出现。

#### 机关和通关

- 一个规则清楚的机关谜题。
- 机关完成后改变地图状态，例如解除楼梯封印或打开门。
- 玩家到达开启的楼梯后完成 MVP。

### 建议的最小内容数量

| 内容 | 数量 |
| --- | ---: |
| 可玩角色 | 1 |
| 普通怪物种类 | 2 |
| 教学战斗 | 1 |
| 其他战斗 | 1～2 |
| 恢复道具 | 1 |
| 装备 | 1～2 |
| 机关 | 1 |
| NPC | 0～1 |
| 可探索地图 | 1 |

### 明确暂不制作

- 第二层及之后的正式内容。
- 魔杖能力。
- 多名队员或队伍系统。
- 复杂技能树和大量技能。
- 完整商店、经济平衡和 NPC 学习技能系统。
- 随机遇敌、随机地图或程序化生成。
- 大量装备栏、装备词条、强化或合成。
- 任务日志和复杂对话分支。
- 正式存档系统；开发阶段可先用重新开始代替。
- 正式美术、复杂动画、配音和完整音乐。

这些功能属于完整游戏设想，但只有在第一层核心循环被验证后才加入。

## 4. 第一层机关提案

MVP 的机关应当只验证“观察—理解—执行—反馈”这个过程，不应成为复杂的独立系统。

### 三开关机关

- 地图中有三个可互动的符文开关。
- 墙上的提示说明正确顺序，例如根据火、月、树的图案排序。
- 按错顺序时，开关复位并给出明显反馈。
- 按对顺序后，楼梯封印消失。

这个方案只需要开关状态、输入顺序和门/楼梯状态，适合作为第一个 GDScript 状态逻辑练习。

## 5. 完成标准

当以下条件全部满足时，MVP 才算完成：

- 新玩家不看开发说明，也能从入口完成第一层。
- 玩家可以连续完成移动、拾取、战斗、装备、解谜和离开本层。
- 从启动游戏到结束画面之间没有阻断流程的错误。
- 战斗中装备带来的属性变化可以被玩家感知。
- 机关成功和失败都有明确的视觉或文本反馈。
- 使用占位素材也能让测试者理解当前发生了什么。
- 一次完整流程控制在 10～20 分钟。

## 6. 技术方向

### 总体原则

- 以 GDScript 编写游戏逻辑。
- 用 Godot 场景组织可复用对象，例如玩家、怪物、道具和交互物。
- 用 Godot Resource 保存适合数据化的内容，例如角色属性、怪物资料、物品资料。
- 场景负责“组成什么”，脚本负责“如何行动”，资源负责“具体数值是什么”。
- 第一版优先清楚和可调试，不急着设计高度通用的框架。

### 初步场景划分

```text
Main
├── Floor01
│   ├── TileMap / TileMapLayer
│   ├── Player
│   ├── Enemies
│   ├── Pickups
│   ├── Switches
│   └── ExitStairs
├── UI
│   ├── DialogueBox
│   └── ExplorationHUD
└── Battle（需要时切换到独立场景）
```

这只是初始边界，不需要第一天就把所有节点建好。

### 建议目录

```text
res://
├── scenes/
│   ├── world/
│   ├── actors/
│   ├── battle/
│   ├── interactables/
│   └── ui/
├── scripts/
├── resources/
│   ├── actors/
│   ├── enemies/
│   └── items/
├── art/
├── audio/
└── tests/
```

## 7. 分阶段学习与实现路线

每个阶段都应当单独运行、测试和提交。不要同时开始多个系统。

### 阶段 1：创建工程与网格移动

成果：玩家可以在一个测试房间内上下左右逐格移动，并被墙挡住。

学习内容：

- Scene、Node 和子节点。
- GDScript 脚本、变量和函数。
- Input Map。
- `_unhandled_input()` 或输入事件。
- `Vector2i`、格子坐标和世界坐标。
- 碰撞检测或移动前占用检查。
- Tween 或简单插值移动。

暂时不做：动画、战斗、背包和正式地图。

### 阶段 2：互动系统

成果：玩家可以面对道具按键互动，拾取后道具消失并显示提示。

学习内容：

- 信号。
- 组（Groups）。
- 可复用场景。
- 基础接口思路，例如不同物体都有 `interact()` 行为。

### 阶段 3：第一层灰盒地图

成果：玩家可以在完整的占位地图中移动，房间、障碍和楼梯位置确定。

学习内容：

- TileMapLayer。
- 碰撞层与遮挡。
- 场景实例化。
- 调试地图尺度和路线。

### 阶段 4：最小 ATB 战斗

成果：玩家接触怪物后进入战斗，可以通过普通攻击分出胜负，再返回地图。

学习内容：

- 场景切换。
- 状态机的基础概念。
- Timer、进度值和速度属性。
- 回合行动队列。
- 信号驱动 UI 更新。

第一版只实现一名玩家、一名敌人和普通攻击。

### 阶段 5：奖励、经验与升级

成果：胜利后获得经验和金币，达到阈值时升级并提高属性。

学习内容：

- 跨场景保存本次游戏状态。
- Autoload。
- 数据和画面表现的分离。

### 阶段 6：背包、道具与装备

成果：拾取恢复药和武器；恢复药可在战斗中使用；装备武器后攻击力提高。

学习内容：

- 自定义 Resource。
- 数组和字典。
- UI 容器。
- 基础数据驱动设计。

### 阶段 7：机关与出口

成果：按正确顺序触发开关后楼梯开启，进入楼梯显示通关画面。

学习内容：

- 状态记录。
- 多个对象之间通过信号协作。
- 动画或音效反馈。

### 阶段 8：整合与试玩

成果：从入口到结束可以连续游玩 10～20 分钟。

任务：

- 修复阻断流程的问题。
- 调整数值和地图路线。
- 添加必要提示。
- 找一位没有参与开发的人试玩。
- 记录玩家卡住、误解或觉得无聊的位置。

## 8. 当前下一步

只开始“阶段 1：创建工程与网格移动”。

阶段 1 的验收清单：

- [ ] 创建 Godot 工程并能运行空场景。
- [ ] 设置游戏窗口尺寸和像素显示方式。
- [ ] 创建测试房间。
- [ ] 创建玩家场景。
- [ ] 在 Input Map 中设置上、下、左、右输入。
- [ ] 玩家每次按键只移动一个固定大小的格子。
- [ ] 按住方向键时的行为明确且稳定。
- [ ] 移动过程中不会接受导致位置错乱的新移动。
- [ ] 玩家无法穿过测试墙壁。
- [ ] 将阶段 1 的成果提交到 Git。

完成这一阶段后，再设计互动系统；现在不需要提前写 ATB 或背包代码。

## 9. 待验证的问题

以下问题不妨碍阶段 1 开工，但应在对应系统开始前决定：

- 一格使用多少像素，例如 16×16、24×24 或 32×32？
- 按住方向键时，是连续逐格移动，还是必须每格重新按键？
- 地图怪物是原地不动、巡逻，还是主动追逐玩家？
- 进入战斗后，探索地图中的怪物是永久消失还是会重生？
- ATB 进度在玩家选择指令时暂停还是继续？
- 玩家战败后，从第一层入口、最近检查点还是存档处恢复？
- MVP 是否需要 NPC；如果需要，他只提供提示，还是也承担教学？
